Probing Recurrent Reasoning: Inside Huginn’s Hidden States

Shane JanneySeptember 2026
Read the paper ↗Explore the results ↓

I started this project because I kept getting stuck on a basic monitoring problem. A language model can give you an explanation for an answer, but that explanation is still another piece of generated text. If the interesting part of the computation never becomes easy to verbalize, a text monitor may be looking in the wrong place.

Huginn gave me a clean way to test that idea because I can let the same model run for more recurrent passes without changing its weights. The surprising part was not just that a probe became good. On my held out set, a linear probe reached 94.6% balanced accuracy at loop 18 while monitors trained on Huginn's written rationales stayed near chance. But the obvious story falls apart one step later: Huginn itself was still around chance on the task, and counterfactual state patching caused zero donor directed answer flips in 24 tested pairs. So the result I am comfortable claiming is narrower, and more interesting to me: late linear decodability without demonstrated behavioral use.

The question underneath the jargon

During inference, a model's weights stay fixed but its activations keep changing. Those activations are not hidden English sentences waiting to be decoded. They are large numerical states. The useful question is smaller: at this point in the computation, is a property I care about linearly readable from the state?

For this experiment, the property is the decision path in a controlled policy task. Some examples are governed by a base rule. Others contain an exception that reverses it. Because I generate the task, I know which path is correct for every example, so I can ask exactly when that label becomes recoverable from Huginn's recurrent state.

Why one good probe is not enough

The annoying part is that both observation channels can mislead you in different ways. A generated rationale might omit something the model used. A probe might recover something the model never used at all. So I wanted to keep three questions separate: what Huginn writes down, what its state makes readable, and what actually affects its behavior.

That separation shaped the whole experiment. I use text monitors for the written explanation, linear probes for the recurrent state, then activation patching as a first attempt to push from correlation toward causality. If those measurements disagree, I do not want to average them into a cleaner story. The disagreement is the result.

How Huginn gives me a compute dial

Huginn repeatedly applies the same transformer core to an evolving hidden state. The parameters stay the same while the state changes from pass to pass. That means recurrence depth works like a compute dial: I can inspect the same checkpoint after 4, 8, 16, or 32 recurrent updates.

The walkthrough below shows the structure I am referring to. It is an architecture explainer, not a recording of the model thinking.

GPT 6 Astra made the question feel less academic

I was already interested in the gap between written explanations and internal state. GPT 6 Astra made that gap much harder to treat as a niche interpretability question.

OpenAI reports in the GPT 6 Astra System Card that Astra has substantially lower chain of thought monitorability than GPT 5.6 Sol in its evaluations. One reason is straightforward: Astra often needs fewer written reasoning steps, and longer traces are generally easier for monitors to inspect. OpenAI also finds that Astra is much better at controlling properties of its own written chain of thought. In the 750 to 1,250 token range, Astra followed those control instructions 60.9% of the time, compared with 16.1% for GPT 5.6 Sol and 1.7% for GPT 5.5 Thinking.

I want to be careful about the connection. Huginn is not a stand in for Astra's architecture, and OpenAI says the increase in controllability does not appear to be differentially caused by architectural changes. My Huginn rationales are also elicited explanations, not the private chain of thought signal OpenAI evaluates internally. The overlap is the monitoring problem itself: if written reasoning becomes a less dependable observation surface, what can activations tell us that text cannot?

OpenAI explicitly points to monitoring methods beyond chain of thought as an important research direction. That is the reason I think this small experiment is useful. It lets me test one version of that question in a model where the recurrent state is accessible enough to inspect directly.

Why I used Huginn

Recurrence itself is not the novelty here. The useful part is experimental control. I can run the same weights for a different number of passes, save the intermediate states, and ask when a known feature becomes easy for a simple classifier to recover.

If e is the prompt representation, h is the recurrent state, and G is the shared core with parameters θ, the update is:

hk = Gθ(hk−1, e)

That lets me separate a change in computation depth from a change in model weights. If a probe gets better late in the run, I know I did not quietly switch to a larger checkpoint. The representation itself changed as the recurrent computation continued.

But that still does not tell me whether the model uses the feature. A probe is allowed to be opportunistic. So the second half of the project asks a harsher question: if I replace the recurrent state with one from a paired counterfactual example, does the answer move with it?

I needed a task where I knew what to look for

Real prompts are messy because the thing you want to measure is usually not labeled inside the computation. I avoided that problem by generating 500 synthetic policy problems arranged into 250 counterfactual pairs. Each problem contains a base rule plus a possible exception. The model follows a short relation chain, checks the endpoint, then decides whether the exception reverses the base decision.

That construction gives me a clean latent label: which path actually governs the answer, the base rule or the exception? I balance that label against the final allow or deny answer, so a probe cannot get a good score just by learning which output token is likely.

I use 350 examples for training, 76 for validation, and 74 for the held out test set. For every example and recurrence depth, I save the answer scores, the generated rationale, and the last prompt token's hidden state after every loop. Runs for the same example share a seed, which keeps the prefix of deeper runs comparable with shallower ones.

Then I look at the same label through three different windows. A regularized logistic probe reads the recurrent activations. A TF IDF classifier and frozen MiniLM encoder read the rationale after I remove the final answer line. Finally, counterfactual activation patching swaps a donor state into a recipient run and measures whether the answer follows the donor. I also keep self patches and unrelated donors around as controls because without them a small logit change is very easy to overinterpret.

Why the train / validation / test split matters

I choose the probe's regularization setting on validation data, refit that configuration on training plus validation examples, then evaluate once on the held out test set. There are only 74 test examples, so a handful of predictions can move the headline number. That is why I show uncertainty intervals instead of pretending the point estimate is exact.

The curve matters more than the peak

Before recurrence, there is basically nothing to celebrate. The prelude probe sits at 50.0% balanced accuracy and the initialized state at 47.3%. Then, in the 32 pass run, the picture changes. Decodability climbs in the middle of the trajectory, reaches 91.9% at loop 16, peaks at 94.6% at loop 18, and finishes at 86.5%.

The peak is easy to quote. I care more about the shape. The path label is not already obvious at initialization and merely carried forward. It becomes much easier for a linear classifier to read after repeated computation. That tells me something real about the representation. It still does not tell me what Huginn does with that representation.

Balanced accuracy

Balanced accuracy is ½(recallbase + recallexception). A constant classifier scores 50%. Here it measures an external probe's ability to recover the decision path. It is not Huginn's task accuracy.

This is where the easy story breaks

The written rationales never show the same late depth jump. At 16 and 32 passes, both text monitors remain far below the state probe, and their 95% intervals include chance at every tested depth.

It is tempting to summarize that as “the reasoning is hidden inside the activations.” I do not think the experiment earns that sentence. What it shows is an observability gap between specific measurement methods. A linear classifier can recover the path label from late recurrent states much better than these two text monitors can recover it from the elicited rationale.

And then there is the sanity check that keeps the result grounded: Huginn itself is not good at the policy task. At 16 passes it answers only 50.0% correctly. A 91.9% probe score cannot mean “Huginn reasons correctly 91.9% of the time.” The probe and the model are being asked different questions.

The GPT 6 connection needs the same restraint. OpenAI's monitorability work studies access to reasoning traces that are different from the elicited rationale I generate here. My result is evidence about this model, this task, and these observation channels. It is not a direct measurement of GPT 6 chain of thought monitorability.

Then I tried to break my own interpretation

A good probe can still be a spectator. To ask whether the decoded feature was doing anything behaviorally useful, I patched recurrent states between paired counterfactual examples. At a chosen loop, the recipient gets the donor's saved hidden state, recurrence resumes, and I check whether the answer moves toward the donor.

The outcome is much less exciting than the probe plot, which is exactly why it matters. I see zero donor directed answer flips across the tested loops. The answer margin moves a little in some conditions, but those shifts do not cleanly separate from the unrelated donor control.

I read this as a null result for this intervention, not proof that the recurrent state never matters. Whole state replacement is blunt, the sample is small, and the model is already near chance on the task. Still, if I am going to claim the probe found something behaviorally meaningful, this experiment did not give me that evidence.

The null result is annoying, but useful

The cleanest statement I can defend is still the same: a task relevant label becomes highly linearly decodable from later Huginn states, while I do not demonstrate that the decoded information drives the model's answer. Anything stronger starts outrunning the experiment.

The biggest problem is task competence. Huginn is near chance on the underlying policy task, so a failed causal intervention is hard to interpret. If I run this again, I want to start with a task the model reliably solves, then repeat the state and rationale comparison across multiple seeds and datasets. I would also use pair clustered uncertainty from the beginning and push harder on lexical shortcut checks.

I also want a less destructive intervention. Replacing an entire token state changes a lot at once. A better follow up would isolate a lower dimensional direction or subspace associated with the path label, intervene along that feature, then compare against random directions with matched norms.

That is the part of this project I want to keep working on. The long term question is not “can I decode something interesting from an activation?” We already know probes can do that. The question is whether an activation monitor can recover information that is both reliable enough to audit and connected enough to behavior to matter.
